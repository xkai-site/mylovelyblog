# 分类发布趋势

首页与分类页的分类名称右侧显示 Sparkline，沿用现有主题色，不使用图表库或新增运行时依赖。

## 数据与统计

- `_includes/category-trend.html` 接收现有 `site.categories` 中每个分类的文章，用 Jekyll 解析后的 `post.date` 按 `YYYY-MM` 分组，输出各月计数。没有预设分类名称；「未分类」使用相同组件。
- `assets/js/category-trends.js` 按浏览器当前年月选择当前月及前 11 个月，按时间升序排列，缺失月份补 0。不会将未来月份或窗口以前的文章计入趋势。
- 文章的新增、删除、分类调整和发布日期修改，随现有 Jekyll 构建／部署更新数据；静态站点不会实时监听仓库文件。浏览器重新打开页面，或恢复页面可见状态时，会检查月份窗口是否需要滚动。
- 每个分类独立按自身峰值缩放。全零序列显示水平线；平滑曲线不会超出相邻月份数值范围。

## 交互与兼容

- 鼠标移至图上显示对应月份与篇数，无坐标轴、网格或常驻标签。
- 手机点图查看数据，点分类名称仍执行原有导航或分类切换。
- Tab 聚焦图表后，可用左右方向键、Home、End 查看月份，Escape 关闭提示；屏幕阅读器可读取完整 12 个月数据。
- 禁用脚本时隐藏图表，原有分类链接仍可使用。标签列表不受影响。

### Jekyll 3.10 参数兼容性修复

GitHub Pages 实际构建发现：`include` 参数不接受 `category[1]`、`category[0]` 这样的数组下标表达式（LiquidJS 预览未拦截）。首页及分类页均已改为先用 `assign` 取值，再将普通变量传给组件。数组下标仍可正常用于 `assign` 与输出表达式。修复后重新通过上述本地浏览器回归；最终以 GitHub Actions 构建结果为准。

当时的本地验证环境没有可用 Ruby / Jekyll，Docker 引擎也未启动，**未执行真实 Jekyll 构建或线上部署**。临时预览不替代现有 GitHub Actions 的最终构建验收；上线后应再次核对分类趋势和文章数量。
